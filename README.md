# claude-mod

Mods for Claude Code: small panes that **show** what your agents do. They never block or rewrite a tool call; at most they warn.

Needs **Claude Code 2.1.287 or later** (function-hook mods, panes, `Svg` element).

## The mods

| Mod | Command | What it shows |
|---|---|---|
| [`factory`](mods/factory) | `/factory [mission\|focus\|arbre\|pipeline\|quotas\|systeme\|journal]`, `/factory <title or id>` | Side panel of all your agents (v2, French labels), tabs on top and every screen stacked top to bottom at the pane's width (no fixed-size drawing, no zoom). **Mission**: counters (working, idle, blocked with the reason, waiting on you, done today, cost today), one card per project (lead, sub-conversations, running agents, context %, model and effort), model share vs the V6 targets, and the conversation list with the All / Live / Problems / Waiting filters. **Focus**: the **Ça t'attend** rows (green PR/MR not merged, question or action waiting on you, lane idle on a red, conflicting or skipped PR, sub-conversations per lead; one native notification per new row), fleet pulse, live timeline (compactions, context over the 250K hand-off mark, blocked, quiet, merged, handed off) and progress today per project. **Arbre** (this conversation or one picked from the list): lead with model, effort bars, price per 1M and context, its sub-conversations, Workflows and agents with model, effort, state, tokens and cost, the architect on call (before a plan, error repeats, before done, calls and tokens read), the bill (every turn vs on call), approvals and guards, warnings, the session log and a status line. **Pipeline**: work in flight per stage (plan, build, review, test/CI, merge) per project. **Quotas**: Claude 5-hour and weekly bars with the forecast from the [`usage`](mods/usage) mod, Codex when available, cost today per model and per project. **Système**: CPU, RAM, GPU, disks and GitLab runner load from the `machine` mod. **Journal**: every session's events, filterable by kind and project. Without the usage or machine mod those boxes say « module non chargé ». Labels, thresholds and which screens show are in `factory.config.json` → `screens` and `waiting`. Screen ideas (counters, Focus, timeline, account pool) from rig-console in [korallis/agent-stack](https://github.com/korallis/agent-stack) (Apache-2.0); no code copied. |
| [`control`](mods/control) | `/control [setup\|usage\|practices\|history\|config] [scan]`, `/config-claude [scan]` | **CONFIG** (`/config-claude`, also a tab of `/control`): everything in Claude Code on this machine, read-only, French labels, top to bottom in the side panel, as a tree category → sub-category → item, each item with its path, modified time, size and full content (Markdown rendered or raw), a search box across names, fields and full text, and a « Changements » list (config files modified in the last 7 days). Ten categories: rules and instructions (global and project `CLAUDE.md` / `CLAUDE.local.md` / `AGENTS.md`, `.claude/rules`, output styles, memory), agents (user, project, plugin, built-in from the docs), skills / commands / workflows, settings merged by precedence (managed > CLI > local > project > user, [docs](https://code.claude.com/docs/en/settings#settings-precedence): value, file that set it, files it overrides; lists merged), documented defaults with their doc URL (« non vérifié » when the docs don't say), hooks and permissions, mods and plugins (loaded or not, version, commands; old copies in `~/.claude/mods` flagged), MCP servers (names, command or URL, scope; env and header **names only**), desktop app preferences (an allow-list of keys; the rest « non lisible depuis un mod »), Claude Control (rules source, `deploy.py`, last deploy backup, `RULES-INVENTORY.md`, and a badge when `~/.claude` differs from the repo). Secrets are masked before anything is written: any settings key matching `token\|secret\|passw\|key\|auth\|credential\|cookie`, every `ANTHROPIC_*` value, token-looking strings; process env vars by name only. SETUP, USAGE, PRACTICES, HISTORY: read live at each scan, so it never goes stale with a rules version. SETUP: « Règles actives » (the title line and version of `~/.claude/CLAUDE.md`, e.g. V5.8), blockers (hook, deny rule, mod deny path), « Mods chargés » (each mod folder: loaded by `CLAUDE_CODE_PLUGIN_DIRS`, installed not loaded, or a copy of a mod loaded elsewhere), hidden rules, then settings (env **names only**, a value only for an allow-list), settings hooks, permissions, repo `CLAUDE.md`, agents, skills, workflows, hook scripts, scheduled tasks, MCP servers, plugins, memory. USAGE: 1/7/30-day model, effort and delegation mix, each metric against the live rule line it measures. PRACTICES: one section per heading of the live `CLAUDE.md`, each line with the evidence it cites (dates, PRs, audits, `PRACTICES` ids) and its measured state, plus a « V6 en attente » panel (kept / changed / dropped) when the rules repo has `docs/V6-CHANGES.md` on main. HISTORY: the rules' version history. |
| [`ci`](mods/ci) | `/ci [refresh]`, `/ci route <repo\|session\|here> <backend-id>`, `/ci clear <target>` | CI routing: the CI backends from your config (GitHub Actions, GitLab.com shared runners, a self-hosted runner, VM runners still coming), whether each is usable now (token present yes/no, runners online, running/pending jobs, Actions per routed repo), and which repo or conversation uses which. A lead conversation or you set the route; each conversation sees its route in the status line and as a short note in its system prompt. |
| [`scenarios`](mods/scenarios) | `/scenarios [S1..] [prompt\|agent\|workflow\|frontmatter\|env]` | Scénarios d'agents: presets of roles -> model, effort, unit (session, sub-conversation, Workflow `agent()`, Agent subagent) and max parallel (S1 Standard V6, S2 Économe, S3 Qualité max, S4 Nuit, S5 Plein régime, plus yours from a JSON file). For each role, the exact settings (Agent call, `agent()` opts, agent-file frontmatter, env vars) and the documented limits, each with its doc URL and "non vérifié" where the docs say nothing; a Copy button for a ready-to-paste snippet. Warn-only toast when an Agent call names no model. |
| [`usage`](mods/usage) | `/conso [aujourdhui\|semaine\|classement\|prevision\|scenarios\|plein\|codex] [refresh]` | Consommation, in French: **Classement** ranks who burned the most (1 h, 4 h, aujourd'hui, 2 j, 7 j, 30 j; by conversation, project, model, agent type, feature or Claude/Codex; tokens by kind, cost equivalent, share, trend vs the window before, subagents counted under their parent); tokens and list-price cost equivalent today and over the week, per hour (heatmap), project, model, kind (main thread, Agent subagent, Workflow agent, sub-conversation), app surface, effort, skill and MCP server, top 10 sessions. Forecast of the 5-hour and weekly limits from the official % (`$.session.usage()`) and the measured pace (last 2 h, today, 7 days) with calme / normal / intense projections; which scenario (S1-S5) fits the quota left before the reset; suggests S5 "Plein régime" when much of the week would be left. Optional status-line entry. **Codex** tab: Codex tokens today and over 7 days, per model, and the plan % Codex writes in its local session files (`~/.codex/sessions/**/rollout-*.jsonl`, the files the codex-hud plugin reads), next to Claude's on one line; « non disponible » when nothing is written (option `codex`: config/on/off). Its parser and price table are a shared module (`mods/usage/lib`). |
| [`band`](mods/band) | `/jauge [refresh]` | Jauge, above the prompt (French labels). One line always visible: a slim context bar (only the next threshold named, never two labels on top of each other) then « ctx 8 % · compact ~16 min · 434 tok/s · 5 h 24 % · sem 14 % » and a ▸ that unfolds three folded sections, each one summary line while closed: Cette conversation (model · effort, agents running/seen, Workflow, PR), Usage (5-hour and week bars, this session's $), Veille (open alerts, the top one); open/closed kept across sessions in the mod's `$.store`; the Mods row stays. In the pane and the older `gauge` style: this conversation's context in tokens and % of the window, where auto-compact sits and how far it is (with « compactage dans ~N min » at the current context growth), markers when it nears the RESUME hand-off threshold (250 K) or a compaction at rest, the burn rate in tok/s at the scopes you pick (this conversation, + its subagents, its Workflow agents, the project with its worktrees, the whole PC) and « semaine X % » when the account reports its 7-day limit. `/jauge` adds the per-scope table (tok/s, /min, /h, list-price $/h, over 60 s and 10 min), the 5 hottest sessions with their compactions, projects, 30-minute sparklines with compaction markers, and each conversation's compactions (time, auto / `/compact` / at rest, context before → after). Optional status-line entry. |
| [`machine`](mods/machine) | `/machine [refresh\|ci]` | Machine, a live view of this PC (French labels): CPU total and per core, RAM, free space per fixed drive, GPU (nvidia-smi, else a Windows performance counter, else « non disponible »), top 5 processes by CPU and by memory with `claude`, `node`, `python` and `git` coloured and totalled, and the local GitLab runner's load (runners online, jobs running / pending) through the `ci` mod's own scanner and config. From these, « agents en parallèle conseillés maintenant : N » with the rules that fired (CPU, RAM, disk, pending jobs) and the caps (4 CI pipelines minus running jobs, 3 `npm ci` / `tsc`). Samples only while its pane is open (every 5 s) or its optional band entry is on (every 15 s, off by default). |
| [`metrics`](mods/metrics) | `/regles [V5.8] [refresh]` | « Les règles marchent ? », in French: whether the rules help, per day over 30 days and per rules version. PRs/MRs merged per day across your repos (`gh` + `glab`), tokens and list-price cost per merged PR (M8, sessions attributed to a repo by their folder), share of Opus / Sonnet / Haiku turns, Agent and Workflow `agent()` calls that name a model (M1), main turns at ≥ 250 K (M2), manual stops, permission refusals (M10), app guard hits, CI gaps (« creux », approximate), BLOCKED / red-twice stops, wake-up calls (M6), compactions. Sparklines with the rules versions from the rules file's git log as `│` markers, an « avant / après » table for any version and a summary row per version. Thresholds, targets, labels and detection patterns in `metrics.config.json`; caches in `~/.claude/metrics-mod`, incremental. |
| [`sante`](mods/sante) | `/sante [refresh]` | Santé des mods, in French: one green / orange / red line on top, then each mod loaded through `CLAUDE_CODE_PLUGIN_DIRS` or installed: loaded or not (its commands in this session), version, commands registered vs the ones its hooks register, last refresh of its cache files, errors (health records, logs, error lists in its outputs), scan duration and approximate CPU over 24 h, cache size on disk (with a cleanup command shown and copied, never run), invalid JSON configs, and the Claude Code version against the mod's minimum. | [`veille`](mods/veille) | `/veille [fil\|mode <x>\|ack <clé\|all>\|coordinateur\|tour]` | Veille, French labels: **Fil** (`/veille fil`, the pane's « Fil » tab, the « Fil » button in band's Mods bar): every conversation's last message in one place, zero model tokens (files only, nothing sent to a model or added to a prompt). A conversation blocked on Julian: Windows notification and an **e-mail** digest (SMTP, your `~/.claude/veille/smtp.json`). Waking a conversation (`claude -p --resume <id>`, off by default) only for what the script cannot do. One line above the prompt with the mode. See [veille](#veille). |
| [`menage`](mods/menage) | `/menage [refresh]` | « Ménage », in French: what Claude work left lying on this PC, read-only. What was kept from the earlier mods when this repo was set up (V6, Oct 2026). Only the **keep** rows are in this repo.

## Install

Copy or symlink a mod folder to `~/.claude/mods/<name>`:

```sh
git clone https://github.com/julian-passebecq/claude-mod.git
# copy
cp -r claude-mod/mods/factory ~/.claude/mods/factory
# or symlink (Windows: mklink /D, as admin or with developer mode)
ln -s "$PWD/claude-mod/mods/factory" ~/.claude/mods/factory
```

Then load it, either for every session with the environment (in `~/.claude/settings.json` under `env`, folders separated by `;` on Windows, `:` elsewhere):

```json
"CLAUDE_CODE_PLUGIN_DIRS": "~/.claude/mods/factory;~/.claude/mods/control;~/.claude/mods/ci;~/.claude/mods/scenarios;~/.claude/mods/guide;~/.claude/mods/usage;~/.claude/mods/band;~/.claude/mods/machine;~/.claude/mods/metrics;~/.claude/mods/sante;~/.claude/mods/veille;~/.claude/mods/menage;~/.claude/mods/cockpit;~/.claude/mods/a-faire;~/.claude/mods/problemes;~/.claude/mods/export-eta;~/.claude/mods/tests-reels"
```

or straight from a clone, with absolute paths (Windows example):

```json
"CLAUDE_CODE_PLUGIN_DIRS": "D:/code/claude-mod/mods/band;D:/code/claude-mod/mods/factory;D:/code/claude-mod/mods/usage;D:/code/claude-mod/mods/scenarios;D:/code/claude-mod/mods/ci;D:/code/claude-mod/mods/control;D:/code/claude-mod/mods/guide;D:/code/claude-mod/mods/machine;D:/code/claude-mod/mods/metrics;D:/code/claude-mod/mods/sante;D:/code/claude-mod/mods/veille;D:/code/claude-mod/mods/menage;D:/code/claude-mod/mods/cockpit;D:/code/claude-mod/mods/a-faire;D:/code/claude-mod/mods/problemes;D:/code/claude-mod/mods/export-eta;D:/code/claude-mod/mods/tests-reels"
```

Every mod here is safe to load by default: none adds text to your prompts or to the system prompt, none blocks or rewrites anything, none calls a model. The one prompt note (`ci`'s route) is off until you set `prompt_note: true`. The external `filetree` (in `vendor/filetree`, not under `mods/`) is the exception you opt into by loading it: while you have a file selected in its tree (you clicked it), each prompt carries one context line with that file's path; the ⊘ button clears it.

To load `filetree`, add `<repo>/vendor/filetree` to the same list, or run `claude --plugin-dir vendor/filetree`.

Or load one as a dev-mod in the desktop app for one session. Python 3 must be on `PATH` (the scanners); `gh` / `glab` are used, when present, for PR/MR and CI state.

Each mod has a config file next to it (`factory.config.json`, `config.json`): rates, thresholds, colors, labels and paths are set there, nothing is hard-coded. `factory` also deep-merges `~/.claude/effort-board/factory.config.json` if you have one, and `control` deep-merges `~/.claude/effort-board/control.config.json` (`paths.user_config`): set `paths.projects_root` (the folder that holds your repos), the optional doc paths and `v6.repo` (the repo whose `main` may hold `docs/V6-CHANGES.md`) there.

### ci

```sh
cp claude-mod/mods/ci/ci.config.example.json ~/.claude/ci.config.json   # then fill the <PLACEHOLDERS>
python -I ~/.claude/mods/ci/scanner/ci.py show --check                  # same data as /ci, from any shell
python -I ~/.claude/mods/ci/scanner/ci.py route ~/code/my-repo gitlab-local --by lead
```

- Config: `--config`, then `$CI_MOD_CONFIG`, then `~/.claude/ci.config.json`, then `ci.config.json` next to the mod, then the shipped example. Each backend has `id`, `label`, `kind` (`github` | `gitlab`), `host`, `runner_tag`, `status` (`active` | `coming-soon` | `disabled`) and `notes`; optional `group`, `concurrent`, `minutes_month`, `public_only`, `check_runners`, `pending_projects`. A value still in `<angle brackets>` counts as unset. Labels and colors are in `labels`.
- Status check: token **presence** only (`gh auth status`, `glab auth status`, or the env variable names listed under `hosts`); a token value is never printed or stored. With a GitLab token: runners with the backend's tag online/offline and their running jobs (pending jobs for the projects in `pending_projects`). With `gh`: Actions availability for the repos routed to a GitHub backend. Missing tools or tokens show as `unknown`. Results are cached (`status_cache`, `cache_minutes`); `/ci refresh` checks now.
- Routing file: `routing_file` (default `~/.claude/ci-routing.json`), one entry per repo path or session id with backend, who set it and when. A session route wins over a repo route; a worktree inside a routed repo follows the repo. `status_line` (default on) turns the status-line entry off; `prompt_note` (default **off**: it adds a line to every request) turns on a system-prompt note naming the route.
- Needs Python 3 on `PATH`; `gh` and `glab` are optional.

### band

- Context, auto-compact threshold and the 7-day limit come from the engine (`$.session.usage()`, `session.measure`: the status line's figures, [statusline](https://code.claude.com/docs/en/statusline)). The threshold is the breakdown's `autoCompactThreshold` (a local `summary` breakdown, no request); without it the band uses `context.autocompact_pct_fallback` and the pane says « non vérifié ».
- Rates come from `scanner/scan.mjs` (Node 22.18+, no dependency), run every `refresh_s`: it reads only the bytes appended to `~/.claude/projects/**/*.jsonl` since its last run (main transcripts, `subagents/`, `subagents/workflows/`), counts each API response once, and keeps its offsets and the last 30 minutes in `cache_file`. `count: fresh` (default) counts input + cache write + output; `all` adds cache reads. A worktree under `.claude/worktrees/` (or a git worktree) counts as its repo.
- Compactions: the transcripts' `system` / `compact_boundary` entries (`compactMetadata.trigger`, `preTokens`, `postTokens`). « au repos » is deduced from the inactivity before an auto compaction, and the at-rest rule (> 200 K, ~54 min idle, 2.1.299) is « non vérifié » in the docs; both are settings.
- **Mods bar** (under the band, and in the `/jauge` pane): one button per mod listed in `launcher.items` of `band.config.json` (default Usine=factory, Conso=usage, Scénarios=scenarios, CI=ci, Control=control, Guide=guide, Santé=sante, Veille=veille, Ménage=menage, Cockpit=cockpit, À faire=a-faire, Problèmes=problemes, Tests réels=tests-reels; each item is `label`, `mod`, `command`). A press runs the mod's slash command (`/factory`, `/conso`, ...), which opens that mod's own pane; the button then reads `Conso ✕`, and a second press runs `/conso close`, which every mod here accepts and which closes its pane. A mod whose command is not in the session is greyed out; pressing it says « non chargé : ajouter mods/<x> à CLAUDE_CODE_PLUGIN_DIRS » (Button has no tooltip prop in the mods API, so a toast and the pane line say it). Why a command and not a direct open: `$.ui.open` / `$.ui.close` act only on the calling mod's own panes and `$.ui.panes()` lists only them ([types for 2.1.299](https://code.claude.com/docs/en/plugins/mods/reference)), while `$.command.run` runs any slash command "as if the person typed" it ([mods API](https://code.claude.com/docs/en/plugins/mods/api)). It queues until Claude's turn ends, so while Claude works the press waits (a toast says so); the opened mod's short command reply lands in the transcript. The open state follows the presses and the commands you type; a pane closed with its own ✕ shows as open until the next press (non vérifié: no event tells one mod that another's pane closed). `launcher.enabled: false` hides the bar.
- **Hand-off helper** (`handoff` in `band.config.json`, buttons only, nothing runs by itself): when this conversation's context reaches `threshold_tokens` (250 K, the RESUME rule) or the forecast puts auto-compact within `eta_min` (20) minutes, an orange line « Passation conseillée » shows under the band with « Préparer RESUME », which runs `/handoff` (the `handoff` skill) through `$.command.run` ([mods API](https://code.claude.com/docs/en/plugins/mods/api)) and is greyed when that command is not in the session, and « Ouvrir RESUME », which shows `handoff/RESUME.md` (session folder first, then repo root) as Markdown in the `/jauge` pane with its age (« mis à jour il y a 3 h » / « absent »). The pane's « Passation (RESUME) » block lists the last 3 hand-offs (`/handoff` runs seen in this session, RESUME written since the conversation started) and compactions of this conversation. Non vérifié: whether the pane's `file://` link opens the file on every surface.
- **Compact band** (`gauge.style: "compact"`, the default): one line, then `sections` (`order`, `enabled`, `open`, `expanded`; `remember: "store"` keeps the open/closed state across sessions in the mod's own `$.store`, `"session"` for this session only). « Cette conversation » reads the model from `$.session.model()`, the effort from `CLAUDE_EFFORT` (non vérifié for mods: absent, only the model shows), agents running = wrote within `running_s` (120 s), the PR from the transcript's `pr-link` entry. « Veille » reads veille's `state.json` and `acks.jsonl` (`VEILLE_HOME` or `sections.veille_home`). A red « À toi : N » opens line 1 when the `a-faire` mod counts N open items (its `summary.json`, `AFAIRE_HOME` or `sections.todo_home`; `""` turns it off). `gauge.mark_labels`: `nearest` (default), `all` (overlapping labels dropped), `none`. `gauge.style: "gauge"` brings back the older two-line gauge.
- Everything is in `band.config.json`: windows, scopes and items of the band and of the status line, thresholds (warn 200 K, hand-off 250 K), colors (theme names), labels, rates. userConfig `config` points to your override file; `band` and `status_line` switch the band and the status-line entry.

### machine

- Sampler: `scanner/machine.py` (Python 3, standard library), one short run per sample. Windows: `NtQuerySystemInformation` per core, `GlobalMemoryStatusEx`, `GetDiskFreeSpace` through `shutil.disk_usage`, a Toolhelp process snapshot with `GetProcessTimes` and the working set; Linux: `/proc`. CPU % are deltas since the previous sample (the mod passes the counters back), so nothing runs between samples. GPU: `nvidia-smi` if on `PATH`, else `typeperf` on `gpu.perf_counter` (an English counter name; on a non-English Windows « non vérifié »), read every `gpu.refresh_s`.
- Runner: `machine.py runner` imports the `ci` mod's `scanner/ci.py` (sibling folder, or `ci.scanner`) and calls its `status()`: same config file, same status cache and `cache_minutes`, same token rules (presence only); only counts come back. `ci.backends` picks the backends (default `gitlab-local`). Children of the local `gitlab-runner` process are shown as a rough count of local jobs (« non vérifié »).
- Advice: `advice.base`, then the first matching rule per metric (`cpu`, `ram`, `gpu`, `disk_free_gb`, `ci_running`, `ci_pending`, `runner_children`), then each cap (`ci_pipelines` 4 minus running jobs, `npm_tsc` 3), clamped to `[floor, ceiling]`. All in `machine.config.json`, with intervals (`interval_s` 5, `band.interval_s` 15, floor `min_interval_s`), colours, levels and labels; userConfig `config` points to your override file and `band` turns the band entry on.

### veille

```sh
node mods/veille/watcher/veille.mjs install          # task ClaudeVeille (per user, no admin); copies itself to ~/.claude/veille/bin
node ~/.claude/veille/bin/veille/watcher/veille.mjs status
node ~/.claude/veille/bin/veille/watcher/veille.mjs mode légère      # or /veille mode légère, or the pane buttons
node ~/.claude/veille/bin/veille/watcher/veille.mjs tour             # one tour now
node ~/.claude/veille/bin/veille/watcher/veille.mjs fil              # rebuild the Fil (fil.json) now
node ~/.claude/veille/bin/veille/watcher/veille.mjs archiver         # rebuild archive.json and print the conversations to archive
node ~/.claude/veille/bin/veille/watcher/veille.mjs uninstall
```

- **Watcher** (`watcher/veille.mjs`, Node 22+, standard library): the task fires every `fire_every_min` (5) through a hidden launcher (`wscript` and a generated `run.vbs`, or `--launcher conhost` for `conhost.exe --headless`), writes `heartbeat.json`, and runs a tour only when the mode's interval is due (otherwise it exits at once). A tour runs `mods/factory/scanner/factory_scan.py --waiting` (own cache `~/.claude/veille/scan_cache.json`), builds the alerts with factory's `waitingRows` plus veille's own (`missed`, `workflow`, `manual`, `exhausted`, `scan`), and writes `state.json` (the tour is its only writer) and `events.jsonl`. `install` copies the watcher, its libraries and factory's scanner and `waiting.mjs` to `~/.claude/veille/bin` and saves the full paths of node, python, gh, glab and claude in `paths.json`, so the task survives a removed worktree and a missing PATH. One tour at a time (the lock is stale when its pid is gone); its own deadline (`tour_deadline_s`, 480 s) kills its children.
- **Missed tours**: the pane and the band line turn red when no fire was seen for two intervals; the next tour adds a `missed` alert and sends one e-mail « veille arrêtée de X à Y » (the 2 Oct incident: the monitors died and nothing woke anyone).
- **Merge** (`nuit-active` only, by the script with `gh` / `glab`, no Claude): candidates are your green, non-conflicting PRs/MRs in `merge.repos`. Right before merging the script re-reads the PR/MR and requires every check `SUCCESS` (GitHub check runs and old-style statuses) or every job of the head pipeline `success` (GitLab: skipped, cancelled, manual or 0 jobs never merge), up to date with the base (`compare` `behind_by` 0, `diverged_commits_count` 0), the head unchanged for `merge.stable_min` (30 min) across tours, the owning conversation idle, and no `merge.markers` label or title tag. Then `gh pr merge --squash --delete-branch --match-head-commit <sha>` or the GitLab merge API with `sha`; at most `merge.max_per_tour`. A private GitHub repo whose CI runs on GitLab has no GitHub checks, so the script never merges it.
- **Wake** (`active`, `nuit-active`, only with `wake.enabled: true`, off by default): `claude -p --resume <session-id> "<brief>"` with no other flag, started detached and hidden in the conversation's folder, output in `~/.claude/veille/wakes/`. Documented in [sessions](https://code.claude.com/docs/en/sessions) and [headless](https://code.claude.com/docs/en/headless) (send a follow-up prompt; a running background session gets it as its next turn). Checked here on a throwaway session: the turn lands in the same transcript with the same model. « non vérifié »: the effort, a permission mode other than the default, and whether the Desktop app shows the turn. A cold resume re-reads the whole context, so the budget is in tokens per hour (`claude_tokens_per_hour`; each wake counts the target's context size), with at most `wake.max_per_row` wakes per alert in `max_per_row_window_h`, then an `exhausted` alert for Julian. Target: the conversation registered with `/veille coordinateur` (brief in [`COORDINATEUR.md`](mods/veille/COORDINATEUR.md)), or with `wake.target: owner` the one that owns the alert; never a conversation active in the last `min_idle_min`. The cross-session inbox socket is not used: its wire format is not documented and a bypass-permissions receiver holds external messages ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)).
- **Alerts to Julian**: a Windows notification (WinRT toast from Windows PowerShell, `watcher/toast.ps1`) for new alerts (only needs-Julian ones in quiet hours and in `nuit-active`), at most 3 per tour; one e-mail digest per tour for the conversations that wait on Julian, each at most once per `mail.repeat_h` (6 h), with the conversation, what it needs, since when and the link. No documented way lets a script send a Claude phone push: PushNotification is a tool Claude calls, and it reaches the phone only with Remote Control connected ([tools reference](https://code.claude.com/docs/en/tools-reference), [Remote Control](https://code.claude.com/docs/en/remote-control#mobile-push-notifications)). `push.claude: true` adds a headless `claude -p --model haiku` that asks for one (costs tokens, « non vérifié »). The e-mail reaches the phone through its mail app.
- **E-mail setup**: copy [`smtp.example.json`](mods/veille/smtp.example.json) to `~/.claude/veille/smtp.json` (outside the repo): Gmail with an app password, port 587 STARTTLS. Then run `veille.mjs test-mail`. Without it the pane says « e-mail non configuré ». The password goes only to the SMTP server: never logged, never in events or errors (scrubbed, with its base64 form).
- **Fil** (`lib/fil.mjs`, `watcher/fil.mjs`, `hooks/fil-view.mjs`): reads the desktop app's session files (`%APPDATA%\Claude\claude-code-sessions`, or the Microsoft Store build's `LocalCache`) and the last 512 KB of each transcript (up to 4 MB when no message is found), at every fire of the task (about 0.5 s for 20 conversations). Settings in `fil`: `projects` ([] = all), `per_project` (15; what waits on Julian is never cut), `preview_chars` (240), `full_chars` (6000), `archived` (`non`, `aujourdhui`, `oui`), `hours` (48), labels. Masked before writing: GitHub, GitLab, Anthropic, OpenAI, Slack, AWS and Google keys, JWTs, private keys, `password: …` / `token=…` / `Bearer …` values and long mixed-case runs (hex SHAs and ids stay). **Ouvrir la conversation**: no documented mod API opens or focuses another session. The desktop app registers the `claude:` protocol and its URL handler routes `claude://claude.ai/epitaxy/<id>` (seen in app 2.42304); a pane `Link` opens only `https:` (the engine draws a `claude://` href as plain text, [reference](https://code.claude.com/docs/en/plugins/mods/reference)), so the button hands the link to the OS (`rundll32 url.dll,FileProtocolHandler`). That it lands on the session: « non vérifié »; « Copier l'id » is the fallback.
- **À archiver** (`lib/archive.mjs`, `watcher/archive.mjs`): at every fire (and `tour`) the watcher writes `~/.claude/veille/archive.json` with the finished conversations the VEILLE conversation may archive in one batch; the script never archives (a script cannot: the VEILLE conversation calls `archive_session` for each id, and its wake brief says « N conversations à archiver, liste dans archive.json »). It reads every open session file of the desktop app whatever its age (about 650 files here), the transcript's mtime and tail, and the mtime of the conversation's `subagents/` and `workflows/` files (background work still writing). A candidate: no activity for `archive.idle_h` (6) hours, the turn ended (no tool call without a result), every PR/MR the app tracks for it merged or closed, or none (links only quoted in the text are not checked). Never a candidate: pinned (the app's `isStarred`) or `autoArchiveExempt`; waiting on Julian (the Fil's signals, `needs_action`, an interrupted turn); a `postTurnSummary.status_category` in `keep_status` (`blocked`); the newest open conversation of its project (`keep_newest_per_project`, so every project stays in the sidebar; the project is the folder it was started in, worktrees folded in); a title matching `role_pattern` (default: an upper-case name then a number, « VEILLE 1 », « MODS 1 »). Each candidate: title, project, id, reason (« PR #21 mergée, terminée, inactive 9 h »), oldest first, with counts of what was kept and why. The Fil tab shows a foldable « À archiver (N) » with the reasons and « Copier la liste des ids »; `/veille archiver` prints the list.
- **Attend Julian, at once**: at every fire (every 5 min, even in `légère`, not only at tours) the watcher rebuilds the Fil and raises one alert per conversation and per question when a conversation waits on Julian: (1) an `AskUserQuestion` with no answer, (2) a `wrap_up` with an `ask` or `blocked`, (3) the app's `needs_action` or interrupted turn, (4) a conversation at rest whose last message ends on a question (heuristic: its last paragraph, after a « Vérifié à HH:MM » line, ends with « ? » or opens with « Tell me », « Should I », « Do you want », « Dois-je », « Veux-tu », « Confirme »…), (5) a probable approval card (a tool call with no result for `fil.approval_min` minutes while the transcript is silent; « non vérifié »), (6) **incohérence**: a session that reports contradicting instructions (« contradicts », « conflict between », « said no merge », « brief says », « incohérence », « contradiction », « consigne contraire », in its last message or its wrap_up), with its own e-mail subject. Each new one: a Windows notification with the title and the question, the e-mail when `smtp.json` exists, a red « attend Julian : N » at the head of band's line, the veille line and the Fil. A factory row for the same conversation is not announced twice.
- Settings: `veille.config.json` (modes and what each may do, intervals, budgets, quiet hours, merge allow-list and markers, wake, mail, labels, colours) deep-merged with `~/.claude/veille/config.json` (mode, coordinator, overrides); factory's `waiting` thresholds apply to the rows. The mod only reads `~/.claude/veille` and runs the watcher's own commands.

### menage

- Scanner: `scanner/menage_scan.mjs` (Node, standard library), run in the background when `/menage` opens and the last inventory is older than `refresh_min` (120), or on ↻. It finds git repos under `repos.roots` (set yours in `~/.claude/menage-mod/menage.config.json`, deep-merged; the shipped value is a placeholder) down to `max_depth`, and runs only read-only git commands with `GIT_OPTIONAL_LOCKS=0` (no index refresh written by `status`). It never fetches: « mergée » is against `origin/main` as of your last fetch.
- Merged means: reachable from the base (`git branch --merged`), or squash-merged (the files the branch changed are identical in the base, or its whole diff has the patch-id of one of the base's last `patch_id_commits` commits), or a merged PR for that branch in the desktop app's session files. Worktrees are always checked; branch squash checks are capped (`squash_check_max` per repo, `squash_check_total`). A branch whose remote was deleted but which is not proven merged stays red.
- Commands are templates in `commands`: `git -C <repo> worktree remove <path>` (never `--force`, so git itself refuses a modified worktree), `git worktree prune` for folders already gone, `git branch -d` for fast-forward merged branches, `git branch -D` only for squash-merged ones (orange « à vérifier », since `-d` refuses them), `git push origin --delete` for remote ones, `rm -rf "<path>"` for orphan folders, old backups and old temp folders. Archiving a session has no documented command outside the app: the row says where to click.
- Folder sizes: on Windows `scanner/sizes.ps1` (PowerShell 7, `pwsh`) reads sizes from the directory listing without opening files; elsewhere, or without `pwsh`, a Node walk. Cached `sizes.ttl_min` (12 h) in `~/.claude/menage-mod/sizes.json`. A first inventory of ~150 repos and ~700 worktrees took about 3 minutes on the author's PC.

Its installed copy picks this up after `node mods/veille/watcher/veille.mjs install`.

### problemes

```sh
node mods/problemes/scanner/problemes_scan.mjs collect            # what the pane and the Veille run (zero tokens)
node mods/problemes/scanner/problemes_scan.mjs import             # your seed sources, once per row
node mods/problemes/scanner/problemes_scan.mjs set P-012 status corrigé --fix "PR #34"
node mods/problemes/scanner/problemes_scan.mjs note P-012 "cause: paths of the main checkout in the agent prompt"
node mods/problemes/scanner/problemes_scan.mjs status
node mods/problemes/scanner/problemes_scan.mjs export             # the register, masked, into the eta repo by PR (/problemes export)
```

- Ledger: `~/.claude/problemes/register.jsonl`, append-only JSON lines, one event each: `add` (a new problem: id `P-NNN`, signature, category, scope, app, title, symptom, cause, fix, status `ouvert` / `corrigé` / `contourné` / `accepté`, source), `seen` (occurrences found by one collection: count, first and last time, up to `max_evidence` examples with session id, file and excerpt), `update` (status, fix, cause… from `set`, or a reopen), `note`. Folding the lines gives one entry per problem (first seen, last seen, count, timeline, notes); the collector writes that fold to `problems.json`, which the pane reads. `cursor.json` keeps the byte offset of each transcript, so a collection reads only what was appended (17 s for a first pass over 14 days and about 2,100 transcripts on the author's PC).
- Detection (`detect` in `problemes.config.json`): AskUserQuestion calls (main conversation or sub-agent), the last line of a main-conversation final that ends with `?`, `BLOCKED:` finals, refused tool calls (permission), tool errors, Workflow results with `agents_error`, outputs of `gh pr checks` / `glab ci …` with failed / skipped / canceled, API errors; from the desktop app's session files (format not documented, « non vérifié »), `postTurnSummary.needs_action` and `sessionPermissionUpdates`. Permission prompts that were accepted are not in the transcripts (« non vérifié »): only refusals and the folders and rules granted are counted.
- Classification (`rules.list`): the first rule whose `kinds`, `match` (regex), `tools` and `sub` fit wins; `per_app`, `key` (first capture group) and `by: "text"` shape the signature; `ignore: true` counts a hit without recording it (routine edit errors). Unmatched hits are counted and their most frequent shapes shown by `status`, so you can add a rule. Categories are a configurable tree (`categories`); a node with `dynamic: "app"` lists one child per app (the first folder under `collect.roots`, worktrees counted as their repo) as a cross view.
- Seeds (`seed.sources` in your `~/.claude/problemes/problemes.config.json`, never in this repo): `markdown` (tables by column name: What / Question / Defect, Effect, Cause, Fix, Still needed, Status, When / Time, Project, Session, Y/N; bullets of sections with `bullets: true`; per-section `category`, `fallback`, `skip`, `title_from`), `incidents` and `findings` JSON; `path`, or `git: { repo, ref, path }`; `optional: true` skips a missing file. Each row is imported once (signature `seed:<source>:<section>:<ref>`).
- Export to eta (`/problemes export`, button « Exporter vers eta » in the pane): the folded register as Markdown under `eta.dest_dir` (`sources/problemes/REGISTRE.md`; past `eta.max_kb` an index plus one file per top category), masked and checked by the export-eta mod's rules, a file with an unmaskable hit held back and named in the index and the PR, landed through the same git flow (fresh eta worktree, branch `export/problemes-<day>-<time>`, PR, squash merge, branch deleted, worktree removed). The two files come from export-eta as byte copies in `lib/eta/` (`scripts/sync-libs.mjs`, drift-tested). The eta path, own e-mails and extra patterns are read from `~/.claude/export-eta/config.json`, so they are set once. History in `~/.claude/problemes/export.json`.
- The pane writes nothing but notes (it runs `note`); statuses and fixes change through `set`. One writer at a time (a lock file in the data folder). The Veille runs `collect` at the end of each tour when the files are in its installed copy (`veille.mjs install` copies them; `problemes.enabled: false` in the Veille config turns it off).

### export-eta

- Setup: write `~/.claude/export-eta/config.json` with `{ "eta": { "repo": "<path of your local eta checkout>" }, "own_emails": ["<you>"] }` (deep-merged over `export-eta.config.json`). Nothing personal goes in this public repo. The exporter needs `git` and an authenticated `gh`.
- Script: `node mods/export-eta/exporter/export.mjs list | pending [--json] | run --mode ongoing|selection|batch [--ids a,b] [--dry-run] [--out <dir>] | status`. The pane and the Veille watcher run the same script; no model is called. `--out <dir>` writes into a folder without git (tests, a look before a real export).
- States: « terminée » = archived, or the app's post-turn summary says one of `finished_categories` (`completed`) and nothing moved for `finished_quiet_min`; « en cours » = the rest active in the last `ongoing_hours` (24); « active » = transcript written in the last `live_s`.
- Batch: the first run sets `since` (older history is never proposed); a batch is the conversations finished after `since` and not exported at their current last activity. `batch_min` (3) or a lead plus all its sub-conversations makes it ready. The Veille watcher (`watcher/export-batch.mjs`) asks `pending --json` each tour and turns a ready batch into one alert with an « Exporter vers eta » button (Alertes and Fil tabs); `auto: true` makes the watcher export it. The installed watcher copy (`~/.claude/veille/bin`) carries the exporter only after `veille install` is run again.
- Confidentiality: `lib/mask.mjs` (rules from `tools/confidentiality_scan.py` plus passwords, cookies, connection strings, JWTs, bearer headers, URL credentials; `extra_patterns` and `patterns_files` add more; every form the tests-reels mod's `findSecrets` flags is masked, tested), then `check()` on the result and again on every file written in the eta worktree. A hit left after masking holds the file back; it is listed in the pane and the PR, never written.
- Git (`lib/etagit.mjs`, also used by the problemes mod through a byte copy): `git worktree add` under `<eta>/.claude/worktrees/export-<day>-<time>` from `origin/main`, branch `export/conversations-<day>-<time>`, commit, push, `gh pr create`, then `eta.merge`: `checks-or-scan` (default; merge when every check is green, or when the repo reports none and the confidentiality pass was clean), `checks`, `never`. The remote branch is deleted and the worktree removed after the merge. Never a push to main, never a force-push.

### tests-reels

```sh
node mods/tests-reels/cli.mjs run-log --app "<appli>" --env "<env>" --procedure "<nom>" --result pass|fail|partial --evidence reports/<preuve>.md
node mods/tests-reels/cli.mjs add env --app "<appli>" --name "TEST tenant" --kind tenant --id tenant=<guid> --url <url>
node mods/tests-reels/cli.mjs add account --app "<appli>" --env "TEST tenant" --login <compte de test> --secret-store wincred --secret-target <adresse>
node mods/tests-reels/scanner/recover.mjs          # recovery scan, counts only on stdout
```

- Local data only: `~/.claude/tests-reels/registry.json` (curated, `cli.mjs add`), `runs.jsonl` (append-only, `cli.mjs run-log`, safe for parallel agents), `recovered.json` (rewritten by the scan, with a per-file cache), `config.json` (your paths, deep-merged). `TESTS_REELS_HOME` or `--data-dir` moves it.
- No secret value anywhere: an account keeps its login and `secret_ref` (store + target, e.g. Windows Credential Manager); the CLI refuses `--password`/`--token`/... and any value that reads like a secret (exit 2). The scan keeps only the kind of a secret seen in clear, the session and the date; passages and commands are redacted, URLs lose their query string.
- Recovery sources in `recovery.sources` (`repo_roots` is a placeholder; set it in your `config.json`). Secret detection is heuristic (« non vérifié »): strong formats plus `password=…` pairs whose value looks random; documentation samples (`EXAMPLE`) and repeated-character fakes are skipped.

## Rules for every mod here

- Show and warn, never block: no `deny`, no rewriting of tool calls or prompts.
- No model tokens by default: nothing added to prompts or to the system prompt unless a setting turns it on (`ci` `prompt_note`, off), no `$.model` call.
- Every pane command accepts `close` (`/factory close`, `/conso close`, ...), used by the Jauge's Mods bar.
- Read-only on your files; each mod writes only its own cache and output folder (`ci` also writes its routing file, on `/ci route` and `/ci clear`; `problemes` appends your notes to its own ledger), plus, for mods with a scanner, its own health record `~/.claude/mods-health/<mod>.json` (`MODS_HEALTH=0` turns it off). No mod deletes anything. The exception you opt into is `veille`'s watcher: in the `nuit-active` mode only it merges green up-to-date PRs/MRs (the rules above), with `wake.enabled` it sends a prompt to a conversation, and it appends one line to `~/.claude/effort-board/manual-checks.md` while the e-mail is not set up.
- No network except `gh` / `glab` for PR state and the GitLab API for runner status (`ci`, and `machine` through `ci`'s scanner); `metrics` runs `gh` / `glab` list calls for merged PRs/MRs and CI runs; `veille` sends e-mail through your SMTP server; `a-faire` runs `gh search prs` for your open PRs (cached 30 min).
- Configurable legends, labels, colors and thresholds.
- Tests next to the code.
